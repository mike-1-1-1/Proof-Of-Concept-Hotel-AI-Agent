- The first lesson I learned during development of this agent was that actually the platform version can matter a lot so that the agent can correctly understand data ingestion. Because when I was developing the agent with the old Microsoft Foundry the agent had a very hard time following the knowledge base when asked with ammenity hours, it was hallucinating the hours. So the easiest way I found to solve this was to simply change to the new Foundry experience where agents have an easier time understanding contextually where to get data ingestion from as knowledge base.

- Another thing I learned is that Agents need a lot more refinement to be able to be production ready, since I noticed the agent I implemented sometimes forgets factual information already stated (before in the chat thread) by the user like guest count or payment method chosen; I'm considering that probably adding Entity Indentification through an AI service from Foundry could be the solution so that the Agent retains key facts throughout the conservation. 

- Additionally, the Agent needs more technical features like image detection to be able to verify official IDs when consulting or creating bookings, actual linkage to real payment method protocols (which are more feasible when the Agent would be directly implemented within a real Hotel service interface like an App or Website) and probably other more production ready features to be actually usable in a real world context.
